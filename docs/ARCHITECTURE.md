# Architecture

How the code fits together: files, the simulation, and how each system works. Update it in the same change that alters any of this. Status and plans are in [ROADMAP.md](ROADMAP.md), history in [CHANGELOG.md](CHANGELOG.md), tests in [TESTING.md](TESTING.md).

## Files and load order

`index.html` holds the markup and loads one stylesheet and 58 classic scripts with `defer`, in this order. All scripts share one global scope (no modules), so top-level names must be unique across files, and top-level code may only use things defined in files loaded before it.

## Simulation

- `loop()` (screen rate) accumulates time and calls `tick()` at a fixed 60 Hz; `tick()` calls `update()`. `render()` runs once per screen frame and must not change gameplay state or call `rnd()`.
- `update()` order: hit-stop/slow-mo (hit-stop starts off: `FEEL.hitstop` 0; the self-test plays with `SELFTEST_FEEL`, the old defaults), players (`updP(p)` for each), `director()`, enemies (`updE`), `bowl()`, `sep()`, star drops (`dropScan`, when `MODE.drops`) and pickups (`pickTick`), cleanup, `MODE.update()` (while someone is alive in play), effect aging.

## Modes, world and camera

- A mode is an object: `update()` runs the rules each step; optional `over()` (KO handling), `bg()`, `fg()` (foreground, drawn over the fighters) and `hud()`. `ARCADE` and `LEVEL` exist; Training still uses `state === 'train'` with no mode rules.
- `CAM.x` is the world x of the screen's left edge. `render()` draws `bg()` in screen space, then the world (fighters, effects) shifted by `-CAM.x`, then `MODE.fg()`.
- `WB` = walls for living fighters (the screen, or a gate). `WW` = world edges for ragdolls. In Arcade and Training, `CAM.x = 0` and both equal the screen.
- A level (`LEVELS[id]`) is an ordered list of chunk ids; `buildLevel()` lays the chunks end to end and makes a run-time copy (`LV`) with encounters (`st` 0 waiting, 1 fighting, 2 done), gates and the checkpoint `cp`. Data is never changed at run time.
- The level camera only moves forward, and stops at the next encounter's lock position, in front of a gate, or at a transition's scene. The ground is still flat (`groundY`).
- **Campaign runs** (run.js): `genRun()` turns a theme into an `LV` of the same shape plus `segs` (each biome's x range), `trans` and `run` ({theme, seed, ng}). Each harder replay (`ng`) adds a toughness level, an enemy per fight and more mini-bosses; the LEVEL mode's `hard()` returns `ng`, and through `hardScale()` the engine gives enemies 40% more health and players' hurts 20% more damage per step. The LEVEL mode's `tally` keeps each player's stats in `LV.stats[slot]` (damage dealt and taken, enemies beaten, best combo, revives) for the victory screen, and its `onKill` turns the theme boss's defeat into the finale: `slow` motion, and every enemy still standing is knocked out. Per biome: a sign chunk, `fights` fight chunks (props scattered from the biome's pool, enemies drawn from its `mix`, toughness rising, a Captain closing each biome but the last, a rare mini-boss), then a transition chunk (or, last, the boss arena and an arch). The layout uses `runRng(seed)`, never `rnd()`, so building a run doesn't shift the fight's random numbers; online everyone builds it from the host's seed. A biome with `lowg` (the moon) has low gravity: `phys` runs up-and-down motion at that speed (`lowG()` in enemies.js), with gravity a little weaker still, so jumps float and reach a bit higher; ragdolls fall slower there too. Sewer and snowy-peak floors are slick (`slick()` in enemies.js keeps knocked-down bodies sliding). Transitions come from the theme's own list (`THEMES[].trans`), filtered by `needs`. A biome with `climb` gets `LV.ramps`: uphill stretches from a screen into the biome to each fight's ledge (fights are placed near the start of their chunk so most of it climbs), cut into pieces of up to 200 px that get steeper from `climb[0]` to `climb[1]` across the biome. **Slopes are drawing only:** the game stays on the flat line `G`; render.js turns on `slopeStart()` each frame and draws every fighter, effect, pickup and prop raised by `upAt(x)` (how high the ground at x is, measured from 200 px into the screen), and the slope look draws its ground along the same line. Slopes start a screen into the biome and end before the next, so the neighbouring biome's flat look never shows one.
- **Online view** (level.js, render.js): in an online level (`ownView()`), each screen follows its own player and nothing holds players back outside fights (the left wall is the start of the run). When a fight starts, or a scene (`cineStart`), `warpIn` brings anyone outside the group's screen (left of `CAM.x`) in. After a scene has carried everyone into a new biome, `backWall()` (the start of that biome) is the left wall for everyone, local or online. Each screen draws from its own view: in an online level only, `render()` swaps `CAM.x` for `viewFollow()` (`VIEW.x`, following this device's player) while `renderFrame()` draws, then puts it back, so the game never sees it (other modes draw straight from `CAM`; the house camera is set while drawing). `levelCamUp` frames only this device's player online; the online house camera (`houseCamera`) follows only this device's player too.
- **Scenes and players:** `cineStart` fixes the scene's players in `LV.cine.ps`; `cineTick` uses that list, so a player who leaves the scene early (st 'free') doesn't shift the others' timings.
- **Platforms in a run** (the launch tower): unlike slopes these are real. `genRun` puts the tower's floors and walls in `LV.terr`, and `levelSim` hands them to the terrain system (terrain.js), so players jump up them like in a house. While the view is over a run's platforms, `levelCamUp` (level.js) raises and zooms out the view (`CAM.y`, `CAM.z`, which only drawing uses: `viewX()` in core.js widens the view around the game's own camera) to frame every player from the highest head to the lowest feet, down to `CAM_ZMIN`; past that it keeps the highest player and `drawOffArrows` (render.js) points to the rest. Away from the platforms it settles back to the ground at full size, and the launch starts only when someone stands on the top deck (`tr.top`, `tr.deck`). The base and crater looks follow `CAM.y` themselves (`CAM_OWN` in biomes.js); for every other look `drawLevelBg` and `drawLevelFg` lower the whole backdrop and foreground by the camera's height, so the ground line stays under the platforms, and stretches the sky's top edge (with the paper grid over it) up to the top of the screen. `levelCamUp` runs during fights too (the crater's fights are on ledges) and leaves room at the top for a boss's health bar.
- **The Volcano** (volcano.js): a biome's `vents`, `rocks`, `ledges` and `descent` (data/themes.js) make `genRun` add steam vents (`LV.haz.vents`, each with its own timing) near each fight, rock ledges (`LV.terr`, `st: 'rock'`) over each fight, lava pools between fights and under the climb down (`LV.haz.pools`), and four ledges stepping down from the rim (the `rim` transition, always the way in because the crater has `enter: 'rim'`, lands everyone on the top one, `tr.land`). A theme boss with `escape` gets `enc.esc`: the ledges of the climb out, the rim's height and the lava's limit. Enemies on ledges follow their target (`followLevel`); revives need the reviver on the same level. **The last stand:** the LEVEL mode's `spare(e)` (asked by `hurtE` when a hit would knock an enemy out) keeps the theme boss at 1 health and sets `LV.escPend`; the next step `escapeStart` freezes every fighter in the `tiki` scene (he says one of the theme's pairs of lines), adds the escape ledges to the terrain and turns on `LV.esc`; he rides up to the rim (`perch`). `escTick` raises the lava (faster when far below the lowest player), sends more of the army down the ledges above you, and has him talk when someone reaches the rim. His death there is the usual finale; then the run ends at the rim (`levelClear` once `LV.fin`). A continue clears `LV.esc` and restarts the fight. All of it is simulation (level clock, `rnd()`), so it plays the same online.
- **Scenes** (`LV.cine`): while one plays, `levelTick` runs only `cineTick()`. Players in a scene have `st: 'cine'` (`updP` skips them; the scene moves them by frame count) and an arriving boss too (`updE` skips it; `inv` keeps it from being hit). A run opens with `drawin`: the pencil draws each player in turn (`p.draw`, then `p.ink` fills the colour). `cineEnd` clears `draw`/`ink` on every fighter, so no sketch outlives its scene. Transitions: the catapult, cannon (players hidden with `p.hide` while loaded), pipe and rope carry everyone to `tr.nx` (the next biome's start); a gate is an ordinary gate (`k: 'door'`) and passing it marks the transition done. Boss intros start when the fight's camera lock is reached: `jump` (a mini-boss falls in, lands with a quake that knocks every player down, and talks) or `pencil` (everyone freezes while `drawPencilIn` in render.js sketches it with a pencil, then it fills with colour and talks). `LV.say` is the speech bubble, drawn by `drawSay` through `MODE.world` (render.js calls it in world space after the effects).
- Gameplay randomness: `rnd()` only. `Math.random()` only for cosmetics (screen shake, Surge sparkle, noise buffer, unseeded run seed).

## Players

`ROSTER` (input.js) is the list of players in a multiplayer game: `{slot, dev, col, d2, name}` where `dev` is `touch`, `kb`, `kb2` or `pad:N`. It is empty in one-player games, and then every device drives Player 1 as before. `init()` builds `PL` from the roster. `devSlot(dev)` routes a device to its player's input slot (`INP[0..3]`); devices without a player are ignored. Each player carries its own `combo`, `comboT`, `meter` and `hpT`; `score` and `maxc` are shared. `MODE.pvp` (Versus) lets players' attacks hit other players through `pvpHit()`. Co-op rules live in modes.js: `coopScale()`, `coopExtra()`, `reviveTick()`. `MODE.pre()` can hold the simulation (the Versus countdown). There is no "current player" (rule R5): functions take the player, and `hurtE(e, d, dr, src, by)` separates the attacker whose momentum adds knockback (`src`) from the player credited with the combo (`by`; throws and flying bodies pass only `by`).

## Input

Keyboard keys and controller buttons come from bindings (`KEYS` built by `applyBinds()`, `padBinds(g)` per controller type). The left stick always moves and aims. When no game is running (menus, pause), `pollPad()` drives `padMenu()`: d-pad/stick moves focus through the visible screen's controls, confirm presses, back goes back or resumes. Switch controllers use A (right) to confirm and B (bottom) to go back.

Every device calls `setA(src, action, on, slot)`. Each slot (`INP[n]`) has `K` (held), `press` (frame pressed), `AIM` and `SRG` (direction and Surge captured at the press). The simulation reads a player's slot through `inputOf(p)`: `INP[p.slot]` offline, `NETIN[p.slot]` in an online match, or the idle `NO_INPUT` while `MODE.locked(p)`. A press stays usable for 12 frames (`wantIn(I, k)`) until a move uses it up (`eatIn(I, k)`).

## Save

localStorage key `orangeArmy.v1` (never change it) holds `{saveVersion, set, best, prog, eco, chr, house}` (version 17). `SET` holds settings (among them `mus` and `vol`, the Music and Sound volumes; `diff`, the difficulty; `tut`, whether the tutorial was offered; `cb` and `big`, colour help and bigger text), feel knobs and touch layouts; `BEST` the Arcade records; `PROG` level progress (`{woods1: {done, score, time, combo}}`). `SET.binds` holds custom keys and controller buttons (null = defaults; see `KEYDEF`/`PADDEF` in `input.js`). `ECO` = `{stars, got, own: [item ids], seen: [item ids]}`; `CHR` = `{cur, list: [fighter|null] x4}`, a fighter being `{name, col (a color item id), ht, head, headType ('donut' or 'full'), lw, stance, eq: {hair, hat, band, scarf, tie, shirt, jacket, gloves, legs, shoes, surge}, wheel: [up to 8 pose ids], prog: {xp, sk: {node id: points}}}`. Item ids are stored in saves, so an id is never renamed (the Surge styles still say `trail-`). `normFighter()` upgrades older fighters (`eq.trail` → `eq.surge`, `eq.pose` → first on the wheel). `migrate()` in `core.js` upgrades older saves one version at a time: v1 had no `saveVersion` and no `prog`; v2 had no `binds`; v3 had no `eco`/`chr`; v4 had three fighter slots; v5 had no `house`; v6 counted house rows from the top; v7 had no house `fills` or `sides`; v8 kept spiral stairs (`spiralR/L`) in `solids`; v9 kept floors in `solids`; v10 fighters had no `headType`; v11 fighters had no `prog`; v12 kept a free ultimate pick in `prog.ult` and the old feel defaults (hit-stop and shake on, bodies 2.5 s). `loadSave()` copies a save into the live objects keeping only the expected shapes. Any new shape change bumps `SAVE_VERSION` and adds a step. Nothing is saved while the self-test runs.

Backups (Settings → Save) are `"OVPA-"` + base64 of the save's JSON. Restoring parses it as data, rejects newer versions, migrates it, keeps the old save under `orangeArmy.v1.before-restore`, writes it and reloads.

## Economy and looks

- Stars change only in `grantStars`/`spendStars`, ownership only in `grantItem`/`buyItem` (`economy.js`). Writes are batched (`ecoSave`).
- `dropScan()` gives each newly dying enemy its stars once (`e.dropped`). Pickups (`PK`) bounce, then fly to the nearest player and are banked on touch. Their rolls come from `dropRoll()`, a hash of `SEED`, `fr` and the enemy's index that never advances `rnd()`, and pickups never touch fighters, so the fingerprints did not change. `collectAll()` banks what's left at the end of a run (`runEnd`).
- A player's look is `p.look` (from `lookOf()`): colors, head size, head type (`hfull`), line width, stance and the item object per slot. It's drawing only: `drawFig` takes a head size, line width and head type (`figHead` draws a ring, or fills it for a full head), then `drawLook` draws items on the joints it reports (`out.hd`, `nk`, `h`, `hb`, `f`, `fb`, `hr`). `drawRag` and `drawTatsu` report their own joints. `lookPose()` blends the idle stance and the victory pose at draw time; its blend state lives in a `WeakMap`, never on the fighter.
- Height (`look.ht`) scales only the drawing in `drawF` (ragdolls keep their size); hitboxes never change.
- Clothes are drawn in layers between the body's own lines: `drawFig(…, lay)` and `drawRag` call `lay.under/back/mid/legs` (from `lookLayers()`) after the far limbs, torso and head, and near leg; the caller then draws `drawLook(…, 'front')` over the near arm. So the far hand sits behind a dress and ties and scarves sit under the near arm.
- Pose wheel: action `e` (T, Select, touch POSE). While it's held on the ground `updP` keeps the player still and stores the aimed direction in `f.wheel.d` (eighths of a turn from up); letting go sets `f.emote = {d, at}` (`at` = the frame it was struck). `wheelSeg(d, n)` turns a direction into one of the n (up to 8) slices when drawing. A new left or right press (pressed at or after `at`; a direction still held from aiming doesn't count), jumping, Surge or attacking clears it. Nothing else reads these, so a fight plays the same with or without poses; `lookPose()` draws the pose from the fighter's wheel and `drawWheel()` the wheel. Older saved key/button bindings without `e` use its defaults.
- Online, `drawWheel()` runs only for the local player (`NET.mySlot`); the pose itself is shared through the simulation.
- The HUD's fading lost hearts (`p.hpT`) and the Surge sparkles are updated in `updP`, never in `render()`.
- `MODE.locked(p)` (Versus after a KO) makes `inputOf(p)` return `NO_INPUT`, an idle slot, so the players can't move.
- Controller menus (`navMove`) pick the nearest control in the pressed direction by on-screen position.
- Surge afterimages (`GH`) remember their owner (`own`) so they can be drawn in the owner's Surge style.
- `withCtx(canvas2d, fn)` points every drawing function at another canvas (store icons, the character preview, Players screen cards).

## Progress (XP, skill tree, ultimates)

A fighter's `prog` (above) is checked by `normProg()` (progress.js): points beyond what its level gives, a row that isn't open, an ultimate step above the level or two ultimate branches reset the tree (points are free to spend again). `buildOf(prog, even)` turns it into what a fight uses: `lv`, `mod` (boosts summed from `SKN[].mod` × points; empty when `even`, which Versus uses), `locked` (every move some node unlocks, minus the ones this tree has) and `ult` (the move for the highest ultimate step bought). Ultimate steps are row 4 of a fighting branch (`n.ult` 0-2): bought in order at `ULT_LEVELS`, in one branch only (`ultBranch`), and they don't count toward that branch's row requirements, so skipping them never blocks a move. `init()` copies each player's `prog` from `ROSTER` (or the current saved fighter in a one-player game) to `p.prog`, notes `p.fi` (the saved fighter on this device that banks the XP; online only the device's own player has one) and calls `setBuild(p)`; Versus calls `setBuild(p, true)` after it. The self-test uses `FULL_BUILD` (everything open, no boosts, the Tornado Kick), so its fingerprints are what they were before the tree.

- **Locked moves:** `pick()` skips a locked move: the string starts over, then the plain (non-Surge) version. Throws: a locked Up Throw or Slam is a Forward Throw.
- **Boosts** are read with `modOf(p, key)` where they act: `boost()` scales a player's hit damage (punch, kick or throw) and marks it `exact` so `hurtE` keeps the fraction; `meterK()` the ultimate meter; `hbox` kick reach; `pick` Surge move cost; `p.smax` the Surge bar; `stamTick` refill; `wind` Winded; `hurtP` damage taken and Second Wind (`swUsed`); the `down` state get-up speed. Zero boosts leave every number exactly as before.
- **XP:** `xpScan()` (in `update()`, where stars drop) adds `XP_KILL` once per beaten enemy to `RUN.xp`; when that lifts a local player past a level it plays `levelUpFx()` (the level-up sound and an entry in `LVFX`, which `drawLevelUps()` in render.js draws as a golden pillar, sparkles and LEVEL UP!; drawing only, outside the simulation). `runEnd()` calls `runXP(extra)`, which adds the level, wave or Versus bonus and `bankXP()` puts it (with the Fortune XP boost) into each local player's saved fighter; Fortune's star boost adds stars there too. Online, every device banks only its own fighter, and the tree travels in the fighter object sent with `hello`, so every device plays the same build.
- **Ultimates** are moves in `A` (data/moves.js). `ULT` with a full meter starts `p.bd.ult`; every one gets `ultBurst()` (branch-colour rings, more and bigger at each step, the third with a ground ring and zoom). An ultimate's hits don't trigger the global hit-stop (`impact(…, ult)`), so many hits at once never slow the game. Their fields: tatsu spins (`rise`, `riseF`, `tv`), `pass` (turn around and hit again every N frames of a dash), `boom` (`shockwave()` at given frames), `fxk` (`ultFx()`: fist sparks, lightning bolts `k: 'z'`, ground dust), `fdmg` (the launching last hit).

## Terrain (floors and stairs)

Every fighter has `f.gy`, the height it stands on: `G` (the floor line) or a surface from `terrain.js`. All ground checks use `f.gy` (`f.y >= f.gy - 1` = on the ground). A surface is a line `{x1, x2, y1, y2}`, flat or a stair ramp; a wall is a vertical line `{x, y1, y2}`; both are kept by column for quick lookup. `phys(f)` moves the fighter, then `terrainStep(f, x0, y0)`:
- walls first (`terrainWalls`): a fighter whose body overlaps a wall's height can't cross its line (kept `T_HALF` px away);
- then climbs (`terrainLadder`): ladders and spiral stairs `{x, y1, y2}`, joined into runs per column. Holding Up or Down (`f.cl`, set in `updP`) beside one gets on (`f.lad`); while on, the fighter moves `CLIMB_SPEED` px a step up or down, stops at the run's ends, and stands where it is (`f.gy = f.y`); jumping or walking more than 20 px from its middle gets off;
- standing on a surface (`f.surf`) and not jumping: Up or Down (`f.cl`, set in `updP`) while walking turns onto stairs going up or down that way (`rampToTake`); otherwise it stays on `f.surf` while that covers its x, then carries on onto a floor at about the same height or more of the same stairs (`surfNext`); nothing = walked off, fall. Without Up or Down, other stairs are ignored, so walking keeps you on your level;
- on the ground, Up while walking into stairs going up that way steps onto them;
- airborne and falling: land on the highest surface crossed this step (`surfCross`). With Up or Down and no sideways input, `updP` walks toward stairs going that way (`terrainRampDir`; on stairs, along them);
- going up: no collision (`f.gy = G` until landing). Down + Jump calls `terrainDrop(f)`, which ignores surfaces for 12 frames.
Modes switch it on with `terrainSet(list)`; `init()` clears it, so Arcade, the Trail and Versus are unchanged (fingerprints too). Ragdolls still fall to `G`. `CAM.y` lets the view look up and `CAM.z` zoom out; `camApply(cx, cy, z)` (core.js) sets world space, zooming about the floor line so z = 1 is exactly the old view. Every mode but House keeps `CAM.y = 0, CAM.z = 1`.

## Head items

Gloves and shoes scale with `limbK(J)` (the fighter's line width against the default), so they cover thick hands and feet. Hats, hair and bands are sized and placed by `itemR(J)` (looks.js): the head's visible outer edge (`hr` plus half the outline width `hw`, both from `drawFig`) less half the item's own ink line, so an item drawn at radius r covers the head's outline exactly at any head size and line width.

## House

`HOUSE` (core.js, saved) = `{bg, cells, solids, floors, fills, climbs, sides, items}`. Squares count `c` from the left of the land and `r` up from the floor (row 0 sits on `G`); each layer maps `"c,r"` to an id. Back to front: `cells` (a wall material filling the square), `solids` (stairs: `stairR/L`), `floors` (a floor along the bottom edge), `fills` (a material inside the stairs' outline, only where there are stairs), `climbs` (a ladder or spiral stairs), `sides` (a side wall along the right edge). Items `{id, x, y}` are placed by their bottom-left square. Barriers (`HSOLIDS`, data/house.js) are drawn as black lines (`houseSolid`); `houseFill` clips a material to the steps (`stairPts`). The land is up to 240 x 60 squares (`HGRID`); `houseExt` measures what's built.

`normHouse(h, any)` (economy.js) is the only way a house is trusted: unknown ids, off-land squares and fills without stairs are dropped; a house saved before version 7 (`flip7`) has its rows turned over. Everything placed is paid with `spendStars` and erasing gives it back with `refundStars` (not counted as earned); backgrounds are bought once with `buyItem`. Painting a wall on stairs goes to `fills`; erasing goes item, fill, side, climb, floor, stairs, wall.

House mode turns floors and stairs into surfaces, sides into walls and climbs into climbs (`houseTerrain`), draws from cached lists (`houseLists`, remade when a layer object changes) culled to the view, and frames every player at draw time (`houseCamera`: zooms out as far as 8%; nothing in House mode's simulation reads `CAM`). Online, `start` carries the host's house (`m.house`), so every device builds the same terrain.

Editor (ui/house.js): the canvas fills the screen; the floor line is raised to `HS_FLOOR` (270 of 420) so the tabs and pieces sit on the floor (`.hsfloor`), with the message, stars and buttons, D-pad and zoom laid over the scene. `hsCam()` gives the editor's camera; three zoom levels (`HS_ZOOM`: 20, 40 or 60 squares across); every square in view is a button (`houseCells`).

## Screen layout

`.screen` stacks its contents in a column. Centered screens are centered by two growing spacers (`::before` / `::after`) rather than `justify-content: center`, so a screen taller than the frame (Settings) scrolls from its top instead of cutting it off. Screens that start at the top hide the spacers. The title screen hides them too: its art (`img/title.jpg`) covers the frame, and with container queries the name and menu are sized in `cqh` (percent of the frame's height) so they stay in the drawing's open space on any screen. The Players and Online screens show `img/multiplayer.jpg` behind a light paper wash, and their cards and notes get paper backgrounds so text stays readable.

## Menu highlight

Buttons are plain until highlighted: orange on `:active`, on `:hover` where a mouse can hover, and on `:focus` while `body.padnav` is set. A controller, the arrow keys or Tab set `padnav`; any pointerdown clears it (input.js).

## Self-test

Open the game with `?selftest`. It resets feel knobs to defaults, plays 3,600 frames of Arcade waves with scripted inputs, adds a Guard, Flanker and Captain, plays 1,800 more frames, and fingerprints positions, health, states, score, wave and the random generator. Then it plays up to 7,200 frames of the Wooded Trail with scripted inputs (it never saves progress) and fingerprints the level state. It shows MATCH when both equal `SELFTEST_EXPECT` in `js/selftest.js` (the one place the expected values are kept), CHANGED otherwise. A refactor must not change them. A gameplay change will: put the new values in `SELFTEST_EXPECT` and mention them in that CHANGELOG entry. `node tools/tests/run.js selftest` runs it (see TESTING.md).

## Still assuming a flat world

Ragdolls, death poses, pickups and enemy AI still treat `G` as the only ground (no enemies appear where there is terrain yet). Levels with platforms would move ragdolls and pickups onto `terrain.js` and teach the AI to use stairs.

## Level creator

Rhett's levels live in the save (`EDIT.levels`) as plain data (format in `js/data/editor.js`) and go through `normLevel` whenever they're loaded, played or shared. A level is one place (biome) and up to 6 parts; a part has a width, platforms (on a 60 px grid, 1 to 5 squares up), scenery from that place, and a fight (enemies with the x they drop in over, `spawn({t, x})`, and the flag where the fight locks the screen). **Playing one** builds it like a run (`buildCustom`; a sign, the parts, an arch) and marks it `LV.custom`: no star drops, XP, scores or unlocks, and, tried from the editor, QUIT, EDIT and the end of the level go back to it. **MY LEVELS** (theme `'mine'`): the Story screen (`themeCards` in ui/themes.js, `THS.mine`), the Players screen (`LB.theme`, `LB.lvl`) and an online room (`NET.theme`, `NET.lvl`) swap the stories for the host's levels (`levelTiles` / `pickedLevel` in ui/rooms.js) and show the red `.nostar` sticker. Online the host sends each guest its levels one message each when they join (`lvl`, kept in `NET.lvls`, checked by `normLevel`; `netLevels()` is the host's own or a guest's copy), and the level picked goes whole in the start message (`level`), so every device builds the same one with `startCustom`. Stories never use custom levels.

## Sound, difficulty and the tutorial

Sound never touches the simulation: audio.js runs from the frame loop and only reads the game (the screen showing, the mode, the active fight, `LV.esc`), so online and the self-test are unaffected. `musWant` picks the song: the screen showing first (victory, game over, the house builder `house`, the Character and Skills screens `dressup`), then the mode (a story plays the biome in view). **Music hand-overs** (`musTrans`, `musGo`): never a silent gap. A jingle (`sting`) plays and leads straight into the next song (`then`): `go` into a game (or `musCue('go')` from the story burst), `bossin` and `bosswin` for bosses, and `tr-<transition>` for each scene that takes you to the next place (`musWant` asks for it while `LV.cine.tr` plays; a smashed gate plays `tr-gate`); a jingle's `end` cuts it short so the next song comes in on its last note. Other changes cross-fade. **Wind** (the `puff` places in `AMB_LOOK`) is nearly still between random puffs, and howls with the peak's gusts (`gustAmt`). Difficulty is part of the simulation: `diffOf()` (modes.js) returns the `DIFFS` entry in force (the host's `NET.diff` online, sent with the room and the start; Normal for Versus and the house; else `SET.diff`), read where enemy health, damage to players, attack spacing, speed, attackers at once, revives and healing are worked out. The tutorial is offline only and only watches the Training Room.

## Online play

Three layers, so each can be replaced on its own (matchmaking, Steam):

1. **Connection** (`net/rtc.js`). WebRTC data channels, reliable and ordered. Devices find each other through several free signaling routes at once (`NETCFG.peerjs`: the PeerJS cloud server; `NETCFG.mqtt`: public MQTT brokers over WebSocket, with a minimal MQTT 3.1.1 client in plain JS). Every signaling message goes by every route with a nonce, and copies are dropped (`RTC.seen`). A host listens as `orangearmy-<room code>` (MQTT topic `orangearmy/v1/orangearmy-<code>`); a guest sends an offer (repeated at 2.5 s and 6 s). No answer in 14 s = NOROOM; an answer but no open channel in 25 s = BLOCKED. `?signal=` and `?mqtt=` point the game at other servers (the tests run local copies). STUN in `NETCFG.ice`; TURN from `NETCFG.relay` (the Open Relay Project's public server; its login is made with `crypto.subtle` HMAC from a shared secret). `rtcDiag()` reports which services answered. Messages are JSON objects and are only ever parsed, never run.
2. **Room** (`net/session.js`). `NET.players` = `{slot, id, name, f (fighter), cid (color), rtt, left}`. Guests say `hello` with `GAME_VERSION` (core.js; bump it with `?v=`) and their fighter; the host replies `welcome` or `deny` (VERSION, FULL, PLAYING) and sends `room` updates (and its own levels for MY LEVELS, one `lvl` message each). Fighters from other devices are checked with `normFighter(f, true)` (shape, not ownership); the host keeps colors unique. **Room size:** `NET.max` (2 to `MAX_ONLINE` = 6, the host's − and +, sent in `room`; never below the players in it); a guest past it gets `deny` FULL. `INP` and `NETIN` have six slots; the HUD draws five or six players' rows smaller. **Ready up:** each player has `ready`, kept by the host: a guest sends `ready`, the host shares the marks in `room` (in the room) or `vr` (on the victory screen). START (and the victory screen's THEME +1) can be pressed only when everyone is ready; nothing starts by itself. A host's option change (mode, story, teams, room size, a team switch) goes through `netOptChanged`, which clears every mark; a player changing fighter clears their own. A match starting clears every mark (`netUnready`).
3. **Lockstep (direct).** `start` carries the epoch, seed, mode, input delay D, the host's `FEEL` (with `NET_FEEL` on top: no hit-stop or shake, bodies clear within 1 s; the Feel sliders are disabled in a match) and the roster. Each device sends `{t:'i', e, f, s, m}` (its button mask for frame f + D, one bit per `ACT`) straight to every device it's connected to: the host to all guests, a guest to the host and to the guests it reaches directly (`NET.links`; the newer guest calls the older ones, `netMesh`/`rtcConnect`). Guests report their links to the host (`links`), and the host passes a guest's buttons to any guest without a direct link to it (and resends recent frames from `NET.hist` when a link breaks). Buttons for a match a device hasn't started yet (they can come straight from another guest before the host's `start` or restart arrives) are kept in `NET_EARLY` and stored when it starts (`netFresh`). Every device stores buttons in `NET.tab` and simulates frame f once it has them from every player still in (`netReady`/`netStep`): `applyMask()` feeds `NETIN[slot]` exactly like `setA`, `inputOf(p)` returns `NETIN` during a match, then `fr++; update()`. D = one trip between the two slowest players (`(rtt1 + rtt2) / 2`) + 1 frame, 2–10. `fr` starts at 0 for every match. Leaving: a guest's `bye` carries its last sent frame; the host announces `drop` (slot, first frame without them, and its copies of their recent buttons) and every device runs `playerLeft()` at exactly that frame: the fighter dies, leaves `ROSTER`, and its body dissolves (`corpseTick` with `f.left`) before it's removed from `PL`. Guests send `simHash()` every 120 frames; the host compares (keeping early ones in `NET.gh`) and a mismatch ends the match (`desync`). After a match, `cmd` (again / cont / room) comes from the host with the frame it was at, so a guest that's behind catches up first.

While `NET.match` is on: the main loop runs `netTick()` instead of `tick()` and never pauses; `devSlot()` maps every local device to `NET.mySlot`; `newSeed()` uses the host's seed; the pause menu hides Restart (guests) and Settings (everyone, so feel settings can't change mid-match).
